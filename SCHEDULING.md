# GitHub Actions scheduling

The prepared workflow is `.github/workflows/monthly-audit.yml`. It is **disabled until explicitly configured**, requires a private repository, and runs only on the repository's default branch. Client inventory and findings must not be uploaded to artifacts of a public repository. The code repository can be public, but live operations must use a private copy until encrypted public-repository artifacts are implemented. Repository visibility has not been changed.

Create the `wordpress-audits` environment and provision the secrets/variables in CONFIGURATION. Enable only after the staging checklist in SETUP passes. Apply suitable environment protections; recurring execution will wait if reviewers are required. Ordinary PR/push CI receives no production scanning secrets.

The cron `47 3 * * *` provides a daily tick at 03:47 UTC (09:17 IST). The engine's monthly due gate runs the first day's audit and retries later daily ticks if that month remains incomplete. Once all enabled sites are complete for that month, ticks make no scan/feed requests. Customize both the registry schedule and cron tick when changing the target timezone/time. GitHub schedules can be delayed and do not guarantee exact delivery. `workflow_dispatch` uses the same due/completion gate; use the CLI without `--scheduled` for an explicitly authorized forced run or `--site ID` for one site.

History is restored from retained `scanwp-private-history` artifacts of completed schedule/manual runs of this exact workflow, repository and default branch. PR artifacts are not eligible. The restore client bounds archives, rejects unexpected ZIP members, validates SQLite and strips GitHub credentials before following the approved signed-storage destination. Missing/expired/corrupt history fails closed unless explicit first-run bootstrap is enabled. The live restore has not been verified against GitHub yet.

SQLite is backed up using its backup API, rather than copying an open WAL database. Both successful and partial runs upload state so failures cannot erase earlier findings. Daily no-op ticks refresh retention. Artifacts retain 90 days, subject to repository policy. Maintain an independent private backup; if all artifacts expire, restore that backup before removing the bootstrap safeguard. Do not silently initialize a new history in place of missing production history.

Workflow concurrency queues overlapping jobs; a six-hour transactional SQLite lease protects local shared-database runs too. Per-site requests have 120-second budgets, size/rate limits and bounded retries. Old running scans are marked interrupted after six hours. SIGINT/SIGTERM requests cancellation; a hard runner kill may leave a running row until recovery. Report failures and incomplete site execution produce nonzero job status and `alerts.json`. GitHub's failed-workflow notifications are the initial alert channel; configure your GitHub notification preferences. No email/Slack messages have been sent or integrations configured.

Missed execution is identified once a due monthly run is more than 24 hours late and incomplete. A scheduler that never starts cannot alert about itself; use a separate uptime monitor if a guaranteed external alert is required. A single process scans sites sequentially; use a server deployment or controlled partitioning before a registry large enough to exceed the runner's time limit. No CI job has been claimed to pass until its actual hosted result is available.
