# Security model and limitations

The engine is an authorized read-only assessment tool. It has no exploit, brute-force, password testing, remediation, remote shell, update installation or account-management capability. Public probes are a fixed, bounded GET list. The registry and runtime invocation must both authorize execution. Only production URLs of selected enabled entries are targeted; staging must be configured/authorized separately.

HTTPX uses certificate verification, disabled environment proxies, bounded request/body/time budgets and controlled retries. A custom httpcore transport connects to validated public IP literals while retaining the original Host/TLS SNI. Private/mixed/IPv6 transition destinations, unauthorized origins and Unix sockets are denied. Authenticated requests never redirect. Tests cover SSRF, rebinding, SNI/Host preservation in a simulated stream, bounded responses, cancellation and retries. The actual TLS handshake with a real staging certificate has not been exercised. DNS resolution still relies on the operating system's resolver behavior; an external process timeout is the final containment boundary.

WordPress inventory tokens are HTTPS-only, 64 random alphanumeric characters, expiring after 90 days, hash-stored, constant-time compared and immediately revocable. Admin rotation/revocation requires capability, nonce and multisite-superadmin checks. The API is GET-only and cannot request file paths or shell commands. Manual admin export can explicitly refresh update metadata or request the earlier collector's official core checksum check; those operations are not exposed by the REST inventory endpoint.

Treat the WordPress host, provider text and archived results as untrusted data. Secrets are passed as process environment values, excluded from config/database schemas, redacted on known credential echoes and omitted from errors. Raw website/configuration/SQL/debug bodies are not persisted; disclosure signatures retain only hash evidence. Redaction is defense in depth, not a reason to send credentials to an untrusted host. The feed parser fails closed on partial/malformed/empty feeds and persists complete snapshots transactionally with provider notices.

SQLite statements use parameters and transactional leases; per-site failures are isolated. Use private directories/ACLs and encrypted disks/backups. `chmod(0600)` is advisory on Windows. The local integrity adapter refuses symlinks/junctions, bounds file count/size and checks modification during reads. On Windows an adversarial filesystem race cannot be fully excluded by a pre-open link check; inspect a separately approved read-only snapshot/mount. No suspicious file is executed.

Report creation stages all formats before publication, escapes HTML/PDF text, rejects unsafe reference schemes/filenames, prevents spreadsheet formulas, rejects secret-bearing document fields and applies private modes. Keep output directories private to prevent local path races. A rename/storage failure can still interrupt publication; treat nonzero execution as incomplete and retain the prior private backup.

Actual isolated WordPress REST/inventory/token behavior has passed in Docker CI, with HTTPS verification against a generated fixture certificate. The proxy trust header in that disposable Docker network is a fixture configuration, not a production proxy recommendation.

Important remaining boundaries: real admin-browser/multisite/vendor verification; live provider/API and hosting verification; authenticated automatic core/package reference acquisition; vendor/premium/must-use identity verification; comprehensive TLS/cipher analysis; independent hosting advisories/backports; Unicode PDF typography; configured business-context risk rules beyond the implemented priority adjustment; and automatic upload/import of Python results into the existing Sites dashboard. Those are not claimed complete. The current dashboard's older response-size limit is separate from the Python engine's per-site 5 MB configurable limit and the bounded complete-feed download.

Do not publish a suspected client exposure as a public GitHub issue. Share minimal redacted reproduction details through a private channel agreed with the owner. No messages are sent automatically by this repository.
