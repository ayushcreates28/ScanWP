# External integration decisions (verified 2026-11-05)

- Python 3.12 remains supported for security fixes through October 2028: https://devguide.python.org/versions/. Available runtime: 3.12.14.
- Wordfence Intelligence v3 Production and Scanner endpoints require Authorization: Bearer from a Wordfence.com account integration key. They return complete feeds, not per-plugin query endpoints. Free personal/commercial usage is documented; rate limits return 429. Production feed provides richer fields. https://www.wordfence.com/help/wordfence-intelligence/v3-accessing-and-consuming-the-vulnerability-data-feed/
- Wordfence terms dated 2026-01-26 require an account/key and preservation of applicable copyright/license notices in copies. Retain per-record copyrights and references in stored findings and reports. Operator must accept applicable terms before a real download; no account creation, terms acceptance, or real feed access is performed by tests. https://www.wordfence.com/wordfence-intelligence-terms-and-conditions/
- Large complete feeds require streaming JSON parsing and atomic replacement of validated feed snapshots; never replace a good feed with a partial/error body. Provider failure and stale data must be visible.
- HTTPX supports custom transports and mocked transports: https://www.python-httpx.org/advanced/transports/. Public-target transport must pin verified DNS addresses while retaining the original TLS hostname. A DNS preflight followed by an unpinned fetch does not meet the DNS-rebinding requirement.
- GitHub Actions selected by the user. Monthly proposed UTC cron is 47 3 1 * * (09:17 Asia/Kolkata). Workflow preparation is not evidence that any unattended job is enabled. Scheduling may be delayed; due/missed detection must be implemented in the engine.
- Cloudflare Sites hosts the existing dashboard but cannot host this CPython/SQLite/PDF workload. Keep the Python service/workflows separate, and disclose the current integration boundary. No hosting change is made implicitly.
- Docker was not found on PATH during initial inspection; isolated real WordPress tests cannot be reported as executed unless a supported environment becomes available.
- Subsequently, the GitHub-hosted Linux runner provided Docker. A pinned WordPress/WP-CLI/MariaDB/Nginx fixture passed the real connector integration test. Exact image digests and reproduction steps are in wordpress-test; actual RED/GREEN artifact summaries are in evidence. This verifies the controlled fixture only, not client staging or a live provider key.
